## ゲーム構造の読取りと手動全画面試験

旧拡張READMEに2026-10-05の読取りとして記録された、実ページの二段iframeとUnity canvasの確認結果です。トップは `https://play.games.dmm.co.jp/game/pjivn_293854`、`iframe#game_frame` は `https://osapi.dmm.com/gadgets/ifr`、その下の `iframe#gameHTML5Canvas` は `https://iv-n-tight.saikyo.biz/app_data/` です。`canvas#unity-canvas` は1280×720で、通常時のinline/computed cursorは `default` でした。

本人が生成パッケージを読み込んだ後、手動で開いたMoonlightカードで通常窓→本人のF11全画面→通常窓を試験しました。この試験の日付は旧文書に個別記録がありません。内部canvasのcomputed cursorを直接観測し、`default → none → default` を確認しました。本人の目視でも非表示と復帰を確認しました。PCカードの全画面では本人がカーソル表示維持を確認し、PCカードの通常窓ではcomputed cursorが `default` であることをDOM観測しました。カードIDの直接読取りとChrome APIのwindow stateは観測していません。

同じ試験の再読込みでは外側frameが空のままcanvas待ちがタイムアウトしました。追加の再読込みは行わず、frame再生成後の再適用は実機未検証です。空になった原因は特定できていません。その後、本人がMoonlightカードを開き直してゲームの復帰を確認しました。開き直し後のcomputed cursorと再適用は未観測です。

- 補助拡張のpause操作、再読込み・frame再生成後の再適用、ゲーム進行操作の維持は実機未検証です。モック検査の合格とは区別します。
- カードIDの直接読取りとChrome APIによるwindow state取得は実機で直接観測していません。
- PC配布カードのアドレスバー非表示popup窓で、補助スクリプトの全画面メニュー操作が成立するかは未検証です。通常のPC利用はDemadoカードから開きます。
